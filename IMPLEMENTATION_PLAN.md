# OpenAuto Multimedia — состояние реализации

## Требования
- Обычная китайская Android-магнитола, ориентировочно Android 14.
- Сенсорные кнопки; управление с руля не требуется.
- Два режима: Bluetooth-музыка и собственный беспроводной Android Auto.
- USB недоступен. Запуск ZLink / TLink не заменяет реализацию приёмника.

## Выполнено в коде
- Тёмное Compose-меню: широкая и телефонная компоновка, обложка и метаданные реального источника, предыдущий / пауза / следующий, системная громкость.
- Проверка Bluetooth/Wi-Fi и сопряжённых устройств, runtime-разрешения, возврат в настройки при постоянном отказе.
- Мост к медиасессиям магнитолы через добровольный доступ к уведомлениям. Содержимое уведомлений не читается и не сохраняется.
- Изолированное ядро :projection: AAP framing/reassembly, version exchange, TLS 1.2, AndroidKeyStore, подтверждение сертификата телефона, служебная сессия и завершение.
- Приём медиаканалов Android Auto: H.264 → MediaCodec/Surface, PCM → AudioTrack, audio focus, касания с масштабированием и несколькими указателями.
- Голосовой ввод: отдельное разрешение RECORD_AUDIO, запись по запросу телефона, ограниченные очереди и ACK-окно, остановка при закрытии сессии.
- Стандартный беспроводной bootstrap: собственная Wi-Fi Direct-группа, Bluetooth RFCOMM/WPP, передача временных сетевых реквизитов, входящее TCP-соединение телефона на 5288.
- Основной запуск без ввода IP; ручное подключение к серверу разработчика на 5277 оставлено для диагностики.
- Приватный экран проекции, сенсорные кнопки громкости/выхода, отмена и повторное подключение, очистка ресурсов при уходе в фон и пересоздании Surface.
- Протокольные и реальные loopback TLS-тесты, включая входящее соединение, медиакредиты и касания во время ожидания входящих данных, микрофон и WPP.

## Что пока нельзя считать завершённым
Совместимость с настоящим телефоном и конкретной магнитолой не проверена. Тесты протокола не подтверждают работу физических Bluetooth/Wi-Fi/кодека/звука/микрофона. Это сборка для проверки приёмника, а не подтверждённая замена ZLink со всеми функциями.

Bluetooth-only зависит от штатных A2DP sink / AVRCP controller. Приложение управляет опубликованной магнитолой медиасессией; оно не превращает стандартный A2DP source в приёмник. Если прошивка не публикует сессию, нужен её OEM-интерфейс.

Звонки требуют настоящего штатного HFP/SCO-подключения. Приложение не подменяет профиль громкой связи фиктивным Bluetooth-сервисом. Отдельные MCU-модули Bluetooth также требуют OEM-адаптера вместо стандартного RFCOMM.

Системная STREAM_MUSIC-громкость может не управлять отдельным MCU-усилителем. Для него также нужен API прошивки.

## Оставшаяся приёмка на устройствах
1. Получить модель магнитолы, фактические API/ABI/прошивку и название/пакет штатного Bluetooth-приложения.
2. Установить APK по сети или с накопителя; USB для работы приложения не требуется.
3. Bluetooth-only: сопряжение, A2DP-звук, реальная медиасессия, обложка/название, play/pause/prev/next, регулятор громкости. Если нет — подключить документированный OEM-адаптер.
4. Android Auto: RFCOMM доступен приложению, группа Wi-Fi создаётся, телефон присоединяется и открывает TCP/TLS; проверить повтор после подтверждения сертификата.
5. Проверить карты, музыку, сенсорные жесты, подсказки навигации, голосовые команды, звонки и возврат из них.
6. Проверить отказ/отзыв разрешений, обрыв Wi-Fi, сон/пробуждение, фон и пересоздание экрана; замерить задержки и нагрев.
7. Исправить выявленные аппаратные/прошивочные особенности и только после этого считать приёмник готовым для этой магнитолы.

## Архитектура и проверка
- :mobile — приложение обычной магнитолы, Compose и Android-адаптеры.
- :projection — протокол, транспорт, TLS, WPP и локальные тесты.
- :automotive — отдельное AAOS-приложение; не является приёмником Android Auto.
- :shared / MyMusicService — существующая заготовка сервиса музыки.

Проверки: `:projection:testDebugUnitTest :mobile:assembleDebug :mobile:testDebugUnitTest`.
Подробный запуск и ограничения: [projection/README.md](projection/README.md).
